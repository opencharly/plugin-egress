# 2026.295.0955 — feat(egress): accept containerd config v4 alongside v2

## Summary

`#ContainerdConfig` pinned `version!: 2`, so the containerd v4 config
`CONTAINERD.md` §3.1 prescribes — the shape the host candies and the
`pod-crabbox*` image contract require — was rejected before the bytes hit disk.
The mutation proof below shows the §3.1 config failing on the previous schema
with `version: conflicting values 2 and 4`.

The kind is now a union of two closed arms. The v2 arm keeps its behaviour (the
Firecracker path still renders it); the new v4 arm types:

- `imports`, as a list of non-empty glob paths;
- the CRI runtime plugin `io.containerd.cri.v1.runtime`: `cni.bin_dirs`,
  `cni.conf_dir`, `containerd.default_runtime_name`, and
  `containerd.runtimes.<name>` with a required `runtime_type`,
  `pod_annotations`, `options.BinaryName` and `options.SystemdCgroup`;
- the gRPC listener under `plugins."io.containerd.server.v1.grpc"`;
- the snapshotter plugin blocks (`native`, `overlayfs`, `btrfs`, `devmapper`,
  `zfs`), sharing the snapshotter set with the v2 arm;
- `plugins."io.containerd.transfer.v1.local"` and its `unpack_config` entries.

The v4 top level is closed with no `grpc` field. A top-level `[grpc]` is ignored
by the v4 daemon, which binds its default socket — the shape that replaced a
host's system socket in a real incident — so that config is rejected, while the
same address under `plugins."io.containerd.server.v1.grpc"` validates.

| file | change |
|---|---|
| `candy/plugin-egress/egress-schemas/egress_containerd.cue` | `#ContainerdConfig` becomes `#ContainerdConfigV2 \| #ContainerdConfigV4`; the v2 arm is preserved; the v4 arm and the shared `#ContainerdSnapshotterName` / `#ContainerdSnapshotterConfig` defs are added |
| `candy/plugin-egress/firecracker_egress_test.go` | v2 and v4 cases, the top-level-grpc rejection control derived from the accepted config, and teeth for `runtime_type` and unpack snapshotters |
| `README.md` | the kind table gains `netfilter_rules` and `containerd_config` (both were missing) |
| `AGENTS.md` | the test inventory gains `firecracker_egress_test.go` |

This schema is compiled at runtime in the plugin's own CUE context and carries
no `@go` annotations or `params` package, so this change has no generated Go
artefact to regenerate.
