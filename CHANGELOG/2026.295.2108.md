# 2026.295.2108 — feat(egress): type the containerd v4 snapshotter where the daemon reads it

## Summary

The v4 arm of `containerd_config` typed the CRI snapshotter under
`plugins."io.containerd.cri.v1.runtime".containerd.snapshotter`. containerd v4 has no such
field on the CRI runtime plugin: it warns `Ignoring unknown key ... key="containerd
snapshotter"` and keeps the value from `plugins."io.containerd.cri.v1.images"`. A v4 config
that named a snapshotter this substrate cannot back therefore passed `verb:egress` while the
daemon silently ran its default — the reverse of the gate's purpose (#15, #16).

This is the residual of the v4 arm landed in #14. The arm's intent is unchanged; the fields
are moved to where the daemon actually reads them.

- Type `plugins."io.containerd.cri.v1.images".snapshotter` against the existing shared
  `#ContainerdSnapshotterName` set.
- Type the real per-runtime override `containerd.runtimes.<name>.snapshotter`
  (`Runtime.Snapshotter`).
- Close the runtime plugin's `containerd` block to its four real v4 fields
  (`default_runtime_name`, `runtimes`, `ignore_blockio_not_enabled_errors`,
  `ignore_rdt_not_enabled_errors`), so the inert runtime-plugin `snapshotter` is REJECTED
  rather than tolerated by an ellipsis.
- Bottom out the v4 `plugins` (plural) map in the v2 arm, so a v4 document mislabelled
  `version: 2` is rejected instead of validating with every plugin setting inert.

| `candy/plugin-egress/egress-schemas/egress_containerd.cue` | images-plugin snapshotter typed; runtime-plugin `containerd` block closed; per-runtime `snapshotter` typed; v2 arm rejects the plural `plugins` map; v2 arm's consumer claim corrected to the additive-union rule |
| `candy/plugin-egress/firecracker_egress_test.go` | the live layer-containerd config as a positive control; rejection controls for the runtime-level snapshotter, an unsupported images-plugin snapshotter, the v2/v4 map mix-up and a garbage top-level key; positive control for the per-runtime override |
