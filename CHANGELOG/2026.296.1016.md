# 2026.296.1016 — feat(egress): type the crabbox containerd config block

## Summary

Type the `containerd` block of the crabbox user config in the vendored
`crabbox-yaml` egress schema.

`#CrabboxYaml` typed only `localContainer`, so a `config:` step rendering
`~/.config/crabbox/config.yaml` with `provider: containerd` had its `containerd:`
block accepted UNTYPED (the top-level `...`) — a quoted int or a bool written as a
string would ship silently. The block now types the keys and defaults of
opencharly/crabbox `internal/cli/config_containerd.go`, with enum arms for
runtime/snapshotter/initMode/nested/stateVolume/gpu/criu/krunNetwork/krunKernel,
and stays open (`...`) for upstream field additions.

Consumer: `opencharly/layer-crabbox`'s `crabbox-containerd-config` candy renders
exactly this shape.

Refs opencharly/plugin-crabbox#15.

## How tested

Gate derived from this repo's own `.github/workflows/` (only `tag-on-merge.yml`;
no per-repo CI), so the repo's Go suite is the gate:

```
$ cd candy/plugin-egress && go build ./...
rc=0

$ cd candy/plugin-egress && go test ./... -run TestEgressCrabboxYaml -v
=== RUN   TestEgressCrabboxYaml
--- PASS: TestEgressCrabboxYaml (0.00s)
ok  github.com/opencharly/plugin-egress/candy/plugin-egress
rc=0
```

New cases: a valid containerd block PASSES; `cpus: "two"` (string), `rootless:
"yes"` (string) and `runtime: podman` (outside the enum) are each REJECTED. The
rejection cases fail on the pre-change schema (the open `...` accepted them), so
the coverage is not vacuous.
